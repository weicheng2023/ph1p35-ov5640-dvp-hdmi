# OV5640 DVP 11 通道逻辑分析仪采集

日期：2026-10-28
目的：直接观察 PCLK、VSYNC、HREF、D0–D7，确认真实 RGB565 数据、
字节顺序、彩条宽度/顺序，以及 PCLK 的真实频率。**本阶段不修改
`0x4740`、`0x503D`、`0x4300` 或 DVP 时序参数。**

## 1. 接线表

LA 探头全部**并联**在摄像头与 FPGA 之间，不拆原连线。优先使用 2×20
IDC40 转接板/测试夹；不要在通电时用杜邦针直接捅排针，避免相邻脚短路。

| LA 通道 | 摄像头信号 | J2 物理针脚 | 连接器侧网络 | FPGA 球位 | FPGA 网络/约束 |
|---:|---|---:|---|---|---|
| CH0 | PCLK | **J2-7** | GPIOB_6 | **F14** | `cam_pclk` |
| CH1 | VSYNC | **J2-21** | GPIOB_18 | **K16** | `cam_vsync` |
| CH2 | HREF | **J2-20** | GPIOB_17 | **K17** | `cam_href` |
| CH3 | D0 | **J2-22** | GPIOB_19 | **K15** | `cam_data[0]` |
| CH4 | D1 | **J2-23** | GPIOB_20 | **K13** | `cam_data[1]` |
| CH5 | D2 | **J2-24** | GPIOB_21 | **L15** | `cam_data[2]` |
| CH6 | D3 | **J2-25** | GPIOB_22 | **L16** | `cam_data[3]` |
| CH7 | D4 | **J2-26** | GPIOB_23 | **P10** | `cam_data[4]` |
| CH8 | D5 | **J2-27** | GPIOB_24 | **P9** | `cam_data[5]` |
| CH9 | D6 | **J2-28** | GPIOB_25 | **P8** | `cam_data[6]` |
| CH10 | D7 | **J2-31** | GPIOB_26 | **R7** | `cam_data[7]` |

电源/地：

- **GND：J2-30**（摄像头 GND，已实测）。若 J2-30 被模组插头挡住，接
  摄像头模组 **P1-1 GND** 或同一 GND 节点；LA 地线尽量短。
- **不要用 J1-11**：它是 VCC_5V。
- **不要把 J2-29（3.3 V）接地或接 LA 信号。**
- 所有 DVP 信号为 **3.3 V LVCMOS**。ATK-Logic 阈值选 **1.65 V**
  （若软件只有 1.8/2.5/3.3 V 档，选 **1.8 V**；不要选 3.3 V）。

## 2. 预期正常波形（先看这些数）

### 2.1 PCLK

- 实测：**48.000 MHz**，周期 **20.833 ns**，高约 7.7–8.9 ns、低约 12–13 ns
  （占空比约 37–43%，随采样率和阈值略有量化差异）。
- 200 MS/s 采样 = 5 ns/点，每个 PCLK 约 4.17 个采样点；250 MS/s = 4 ns/点。
- 20/25 ns 交替是 5 ns 网格的量化，不是抖动；`min=15 max=45 ns` 里包含
  行边界丢沿，不能当抖动证据。
- 旧文档的 **50 MHz** 是 20 ns 粗量化的误读；2.3 GB CSV 的
  `24,000,131 rises / 0.5 s` 也正好是 48.000 MHz。SDC 的 50 MHz 偏保守。

### 2.2 VSYNC

- 当前 `0x4740=0x22` 实测：**高有效**，空闲低，约 **66.7 µs** 高脉冲，
  周期 **33.333 ms（30 Hz）**。
- 帧开始 = VSYNC 上升沿；下一帧开始 = 下一个上升沿。
- 若看到空闲高、短低脉冲，说明实际是低有效，参数/接线需重新核对。

### 2.3 HREF

- 实测：周期 **66.665 µs = 3200 PCLK @48 MHz**；高约 **40 µs = 1920 PCLK**，
  低约 **26.665 µs = 1280 PCLK**。
- 16:24 位流假设 **低有效**：行开始 = HREF 下降沿，行结束 = 上升沿；
  低相位正好 1280 PCLK = 640 像素 RGB565 的 1280 字节。
- **但极性仍未最终证明**：
  - A. 低有效：低相位 1280 字节就是有效彩条数据；高相位 1920 字节是消隐。
  - B. 高有效（datasheet `0x22` bit1=1）：高相位前 1280 字节有效、后
    640 字节 dummy；低相位 1280 PCLK 是消隐。此时低有效位流会抓到消隐，
    长度也正好 1280，LED4 仍会熄灭——**是假成功**。
- 16:24 位流的 LED4 熄灭只检查长度/行数，不检查像素值，**不能区分 A/B**。
  必须抓 HREF 两相 + D0–D7，看哪一相出现 8 色条，才能定极性。
- 垂直消隐期间 HREF 有一次 **1.373 ms** 长高；低有效时这段不产生有效行。

### 2.4 D0–D7

- 在 **PCLK 上升沿**采样；数据应在上升沿前稳定，通常在下降沿后变化。
- 不是每个 PCLK 都必须变化：连续相同字节（纯色彩条内部）会保持不变；
  消隐期间保持最后值或 0 都正常。判断有效性看 HREF，不看数据是否跳变。

### 2.5 RGB565 字节

`0x4300=0x61`：第一字节高字节 `{R[4:0],G[5:3]}`，第二字节低字节
`{G[2:0],B[4:0]}`。

| 像素 | RGB565 | 第一字节 D7..D0 | 第二字节 D7..D0 |
|---|---:|---:|---:|
| 红 | F800 | F8 | 00 |
| 绿 | 07E0 | 07 | E0 |
| 蓝 | 001F | 00 | 1F |
| 白 | FFFF | FF | FF |
| 黄 | FFE0 | FF | E0 |
| 青 | 07FF | 07 | FF |
| 品红 | F81F | F8 | 1F |
| 黑 | 0000 | 00 | 00 |

一个像素占 2 个 PCLK；640 像素 = **1280 字节/行**。
一帧 480 行 = **614,400 字节 = 307,200 像素**；30 fps 时有效数据率
**18.432 MB/s**。

### 2.6 彩条

- `0x503D=0x80`：bit7=1 使能测试图案，bit[3:2]=00 标准 8 色条，
  bit[1:0]=00 color bar。`0x4741` 未写入，保持默认。
- 8 条竖条，但**具体顺序和每条宽度不能仅凭 checker 假设认定**。
  checker 假设白/黄/青/绿/品红/红/蓝/黑、80 px/条；这只是一个假设。
- 如果彩条覆盖 640 像素，条宽 80 px（160 字节）；如果覆盖 1000 像素，
  条宽 125 px（250 字节）。LA 的 run table 会直接给出真实值。
- 正常时每一行的彩条规律相同；行首/行尾可能有 dummy/padding，需看
  HREF 有效窗口的第一字节。

```text
                     66.7us                33.333ms
HREF  (低有效?) ‾‾‾‾\__________________________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
                    low=1280 PCLK (26.67us)      high=1920 PCLK (40us)

                 20.8ns

```

注意：上图是 16:24 位流的**假设**，不是已证明的事实。HREF 低相位宽度
（1280 PCLK）是实测的，但“低相位=有效数据”仍需 D0–D7 彩条确认；
VSYNC 高有效是实测的。极性 A/B 两种解释见 §2.3。

## 4. ATK-Logic 设置

### 4.1 两个实验

**实验 A：一行/几行数据（先做）**

- 11 通道全开，200 MS/s，阈值 1.65/1.8 V。
- 触发：HREF 下降沿（低有效假设），预触发 10 µs。
- 采集：100 µs（约 1.5 行）；内存约 20k 采样点，CSV 很小。
- 目的：确认 PCLK 频率、HREF 低相位字节数、D0–D7 是否稳定、彩条 run。

**实验 B：完整帧结构**

- 触发：VSYNC 上升沿（高有效假设），预触发 1 ms。
- 采集：35 ms（一帧 + 余量），200 MS/s 约 7M 采样点。
- 若 ATK 内存不够，改用 100 MS/s 看帧/行结构；数据字节再用实验 A 的
  200 MS/s 结果。不要一上来用 Stream 模式抓 0.5 s，CSV 会到 GB 级。

### 4.2 探头/信号完整性

- **单根短地**：LA 只留一根尽量短的地，接到 J2-30 或摄像头 P1-1 的就近
  GND；不要多个地夹在不同点形成环路。2026-10-28 的 12–16 ns 高相位毛刺
  很可能就是地回流/多地和 PCLK 耦合造成的。
- 每个探头地线尽量短，信号+地成对；11 根线不要散成一束长杜邦线。
- 探头夹在**摄像头侧、47 Ω 串联电阻之前**；夹在 FPGA 侧会把 47 Ω 和
  走线电容算进去，边沿更差。
- 阈值选 **1.4–1.8 V**（摄像头 IO 2.8 V）；不要用 3.3 V 阈值，否则
  高电平宽度会被量短。
- 200/250 MS/s 对 48 MHz 只有 4–5 点/周期，足够恢复字节，但边沿时间/
  建立保持只能做粗略判断；需要精确边沿时用示波器。
- 不要在信号线上串入大电阻/电容；LA 是高阻并联观察。

## 5. 自动分析

```bash
perl tools/analyze_dvp_la.pl capture.csv
```

默认映射 CH0=PCLK、CH1=VSYNC、CH2=HREF、CH3..10=D0..D7，HREF 低有效、
VSYNC 高有效、PCLK 上升沿采样。常用选项：

```bash
# 如果实测 HREF 高有效
perl tools/analyze_dvp_la.pl capture.csv --href-active=high
# 如果数据在 PCLK 下降沿更稳定
perl tools/analyze_dvp_la.pl capture.csv --edge=fall
# 只分析前 3 行，不打印太多像素
perl tools/analyze_dvp_la.pl capture.csv --max-lines=3 --show-pixels=16
```

脚本输出：

- PCLK 周期/频率/高低电平统计；
- HREF 有效行数、每行字节数直方图、有效宽度；
- VSYNC 帧数、每帧行数、周期；
- D0–D7 高/低计数（判断是否某位粘死）；
- 第一行/最常见行的原始字节、phase0/phase1 像素；
- **实际 run table**（起始像素、长度、RGB565、R/G/B）；
- 与 checker 假设的对比：first error、字节交换、位反转、像素偏移。

run table 是判断“checker 假设是否错误”的关键：如果实际是 125 px/条或
颜色顺序不同，checker 的 80 px/固定顺序假设就不成立。

## 6. 故障诊断表

| 波形 | 可能原因 | 先检查 | 下一步 |
|---|---|---|---|
| PCLK 无波形 | 摄像头未供电/未出时钟；探头/地错；PWDN/RESET 错 | J2-29=3.3V、J2-30=GND、PWDN/RESET 电平；换已知通道 | 用 `top_cam_id` 确认 SCCB；示波器看 F14 |
| PCLK 频率不对 | PLL/分频寄存器与假设不符；测量窗口太短 | `0x3035/36/37/3108` 回读；1 ms 计数 | 以 LA 实测重算帧率/带宽，不改配置 |
| VSYNC 无周期 | 摄像头未出图；HREF/VSYNC 接反；触发设置错 | 通道映射、极性、`0x4740` | 先抓 100 ms 自由运行 |
| HREF 一直高/低 | 极性假设错；无行输出；探头接错 | HREF 在行间是否有 15 kHz 变化 | 改 `--href-active`，确认实际有效相位 |
| D0–D7 全 0 | 数据线未接/摄像头未输出；PCLK 采样点错 | 探头、GND、PCLK 边沿 | 换 `--edge=fall`；查模组座 |
| D0–D7 全 1 | 上拉/断路/错接；模组未驱动 | 断电测通断；看是否某根线浮空 | 逐根核对 J2 针脚 |
| 只有部分位变化 | 某根 Dx 断/错位；位映射错 | 逐位高/低计数；已知彩条值 | 对照 J2 表逐根查 |
| 每行字节数≠1280 | HREF 有效相位宽度不同；dummy/padding；极性错 | 低/高相位 PCLK 数；行首字节 | 用真实宽度决定 checker 期望 |
| 每帧行数≠480 | VSYNC 极性/帧边界错；垂直消隐计入 | 行数直方图；VSYNC 边沿 | 以 LA 行计数为准 |
| 两字节交换 | `0x4300` 不是 0x61；FPGA 配对相反；脚本 phase 错 | 原始字节；脚本 byte-swapped 匹配数 | 修 RTL/脚本，不改摄像头除非寄存器错 |
| 位序反转/映射错 | D0..D7 接线顺序错；位反向 | 逐位计数；bit-reversed 匹配数 | 按 J2 表重接/改约束 |
| 彩条顺序不符 | 实际测试图案顺序与 checker 假设不同 | run table 的颜色序列 | 以实际顺序更新 checker，不归因摄像头 |
| 彩条边界偏移 | 条宽不是 80 px；行首 dummy；像素相位错 | run table 的长度/起始 | 用真实条宽/相位；检查首字节 |
| 随机错误/跳变 | 采样边沿/建立保持；地回流；杜邦线振铃；PCLK 太快 | 降低线长、加地、换边沿；看错误是否随位置固定 | 固定位置=映射/相位；随机=信号完整性 |
| 行帧对但 checker 失败 | checker 期望（顺序/宽度/相位）错；FPGA 配对错 | LA 原始像素 vs checker 期望 | 先修 checker 假设，再谈 RTL |

## 7. 验收标准

只有同时满足以下条件，才认为 DVP 数字路径基本正确：

1. PCLK 稳定，频率与行/帧统计自洽（**48.000 MHz**，周期抖动小）。
2. HREF 周期 66.665 µs / 15 kHz；**低相位 1280 PCLK、高相位 1920 PCLK**；
   并且用 D0–D7 彩条确认哪一相是有效数据（A/B 极性，见 §2.3）。
3. VSYNC 周期 33.33 ms，每帧 480 个有效行。
4. 每个有效 PCLK 的 D0–D7 在上升沿稳定；无大批 edge-coincident 变化。
5. 两字节还原出的 RGB565 在彩条内部稳定，run table 的条宽/顺序可重复。
6. 字节顺序、位序、像素相位中至少一种解释能让整行彩条完全自洽；若只有
   checker 假设不符，而原始数据自洽，则问题在 checker 期望，不在摄像头。
7. **不能只用 LED4 熄灭判定通过**：LED4 只查行长度/行数/极性配对，不查
   像素值；必须同时有 D0–D7 彩条证据。

达到后，才进入 HDMI 时序/显示链路；不要为了让 LED4 熄灭而改摄像头配置。

## 8. 2026-10-28 实测结果（失败，未收敛）

本次 11 通道尝试没有通过。详细现象/推测/证据见
`verification/board/evidence/20261028_dvp_11ch/README.md`。要点：

| 项目 | 结果 |
|---|---|
| PCLK | **48.000 MHz**（13:41 200 MS/s、13:58 250 MS/s 两次一致） |
| 13:58 HREF 包络 | 15 kHz / 66.676 µs；低 26.676 µs = 1280 PCLK；高相位有 12–16 ns PCLK 串扰 |
| 13:58 VSYNC | 无效：每 66.66 µs 一个 4 ns 尖峰，不是 30 Hz |
| 13:58 D0–D7 | 全 0（13:41 同批数据是跳变的，故更像探头/接线状态） |
| 14:36 HREF 单测 | **29.53 kHz**：30.856 µs 高 / 3.002 µs 低 / 33.858 µs 周期 |
| 14:36 的 PCLK | 未抓，不能证明是 48 MHz 还是默认模式的 ~41.5 MHz |

**已确认的现象**：PCLK 48.000 MHz；13:58 HREF 包络 15 kHz/1280 PCLK；
14:36 HREF 稳定在 29.53 kHz；13:58 VSYNC 不是 30 Hz。

**推测（未证明）**：14:36 的 29.53 kHz 更像摄像头复位后回到默认
1280×960 时序（30.856 µs ≈ 1280 px @41.5 MHz；960 行 ≈ 30.8 fps），
而不是接地干扰直接改变频率；重新插拔/掉电后 FPGA 没有重跑 SCCB 是
最可能的机制。用户“接地太多”的假设可以解释毛刺，但不能单独解释
稳定的 29.53 kHz。

**保留项**：16:24 位流的 LED4 熄灭不等于彩条数据正确；HREF 低有效
（A）和高有效（B）都能让 1280 长度检查通过，必须用 D0–D7 两相对比
才能定极性。复测步骤见证据文档 §5。
