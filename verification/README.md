# 验证说明

验证分三级，**证据分开存放，结论不可互相替代**。

| 级别 | 位置 | 内容 | 通过标准 |
|---|---|---|---|
| 仿真 | `../fpga/sim/` | Testbench、测试向量、仿真日志 | 断言/比对通过 |
| 静态检查 | `static/` | lint、CDC、时序报告与豁免说明 | 无未豁免问题；时序收敛 |
| 上板 | `board/` | 测试计划、接线、步骤、照片/视频、日志 | 实际采集与显示正确 |

## 1. `board/`：真实硬件验证

当前文档：

- `wiring-check.md`：接线电气检查表（待执行）。
- `bringup-sccb-id.md`：最小 SCCB Chip ID 上板步骤与 LED 判读（待执行）。

建议结构：

```text
board/
├── test_plan.md                 目标、接线、步骤、预期、判据
├── bringup_checklist.md         上电顺序与逐项检查
└── evidence/
    └── YYYYMMDD_<topic>/        原始日志、照片、结论
        ├── README.md            环境、步骤、结果、结论
        ├── logs/
        └── images/
```

每个证据目录的 `README.md` 至少记录：

- 日期、操作者
- TD 版本、器件型号、工程 commit（Git 就绪后）
- 接线与跳线状态
- 实际步骤与观察结果
- 结论：通过 / 失败 / 部分通过，以及失败现象
- 未验证项

## 2. `static/`：静态检查结论

当前记录：

- `top_cam_id_build_2026-10-24.md`：ModelSim 仿真、TD 综合/布局布线/时序/位流结果。

- 报告原件体积较大时留在 `build/reports/`，此处保存**结论摘要 + 复现命令**。
- 命名：`<tool>_<date>_<summary>.md`。
- 每条告警需说明：已修复 / 已豁免（理由）/ 待处理。
- 时序报告需记录目标频率、实际 WNS/TNS、约束版本。

## 3. 规则

- 不以“路径检查通过”代替综合，不以“综合通过”代替时序收敛，
  不以“时序收敛”代替上板成功。
- 只放截图不给复现步骤的记录不算验证证据。
- 失败结果同样归档，不得只保留成功记录。
- 未执行的项目在 TASKS.md 中保持未勾选，并注明原因。
